> 本规范由管理员（老爹）于 2026/10/31 明确立项并强制执行。
> **铁律执行原则**：每次启动、重启、维护或扩展饥荒工坊拉取任务与代码生成前，**必须首先完整读取本规范**，严格遵循架构标准，禁止遗忘，禁止擅自简写或截断！

## 一、战略优先级与文档查阅核心（老爹最高指令）

1. **【第一绝对优先级】：文档即范式（Doc-as-Skill 架构）**
   - **文档与 Skill 深度合一**：彻底终结“理论文档与实战代码脱节”的两张皮问题！每一篇公开文档本身就是最高水准的技术解析博客，同时又是具备完整防御体系、可即插即用的工业级黄金 Skill。
   - 文档的立项目的是供所有人无障碍查阅学习，必须做到：脉络清晰、层级有序、任何人点进就能按图索骥，复制即用。
   - 严禁空洞理论与占位符流水账，每一篇沉淀都必须具备真正的生产级参考价值！

2. **【研读总结原则】：有迹可循，吃透精华，跳过重复**
   - **绝对质量标杆（老爹金标准）**：每一篇必须严格贯彻第四章规定的**六大标准板块**（架构哲学、数学算法、生产代码、对比矩阵、演进分支、踩坑指南）。
   - **坚决禁止垃圾流水账**：严禁产出“无钩子、纯数值改动、无核心算法剖析”的无用流水账！凡无法提取实质技术模式的 MOD，一律在流水线前置过滤，严禁入库！
   - **深度提炼要求**：必须包含可直接运行的完整生产级代码片段和深层架构解析，严禁仅列出“某某钩子使用了 1 次”等几行空洞清单！

3. **所有人公开可查，绝对禁止信息折叠**
   - 文档面向全体开发者与社区玩家，严禁出现类似“篇幅所限仅展示前 N 个，其余详见桌面”等偷懒或截断行为。
   - 所有已研读的 MOD 必须 100% 具备公开索引和直接跳转路径。

4. **按实际功能维度动态扩展分类（不局限于固定类目）**
   - **严禁生搬硬套死磕类目**：遇到现有分类不能精准表达的技术领域（如：`Boss战斗与AI决策`、`音效与视觉特效FX`、`农场与世界生态模拟`、`物理与水域运动` 等），必须主动创建全新的细分功能专题！
   - 领域母本研读（`study_<机制/领域名称>.md`）除在总索引登记外，必须按其实际功能精准归入对应专题；首发代表作 ID 标在元数据中，后续同类 MOD 均作为变体演进并入该母本。
   - 目标只有一个：构建业界最权威、最精准、真正按实际功能随时检索的百科全书级查询文档！

5. **分类必须具备全景横向架构综述**
   - 每个分类目录下必须维护专有的 `README.md`，不能只有模组列表。
   - 综述必须横向提炼：
     - **设计范式与生命周期管理**：各 MOD 公用的注册时序、环境隔离。
     - **底层关键 Hook 与组件**：如 `AddPrefabPostInit`、`AddClassPostConstruct`、`BufferedAction`、`net_var`、`RPC`。
     - **高频避坑与生产级守则**：时序空指针防御、网络同步广播开销、存档污染防范。

## 二、自动化流水线脚本规范（daemon_8_workers.py：6+1 架构）

1. **前置硬核准入过滤链（杜绝水货进入候选池）**
   - 候选池前置校验：只有涉及 StateGraph 状态机切面、网络 RPC/Netvars 同步、空间仿射投影、复合 AI 行为树、容器拓扑或动态 UI 渲染的硬核 MOD 才准许入池。
   - 坚决拦截过滤：纯文本汉化包、单纯数值修改（如 999 堆叠、无限耐久、血量倍率覆写）直接在前置阶段物理剔除，不强凑伪数字。

2. **6+1 生产者-消费者母本归约流水线架构**
   - **6 个分析抓取工作线程（Worker 1~6）**：
     - 并发进行工坊源码静态解析与单 Mod 技术点提炼；
     - 解析成果统一写入本地暂存缓冲区（`state/staging_skills/` 或临时待存区），**禁止 6 个并发线程直接改写最终黄金母本库**，杜绝并发写冲突与碎片化生成。
   - **1 个母本仲裁归约专属线程（Reducer Worker 7）**：
     - 专门持续监听待存缓冲区中的新成果；
     - 依据本规范第四章的演进铁律进行**规范性总结与母本归约**：
       - 若属于全新领域 -> 建立该领域的唯一黄金母本；
       - 若属于已有领域 -> 执行【增量演进与变体扩展】或【追加方案对比矩阵（Trade-off Matrix）】，实现母本进化，彻底保证全库“一领域一母本”的至高纯度！
   - **1 个底座看门狗与总账同步线程（Master Worker 8）**：
     - 负责 SteamCMD 串行加锁调度、双总账原子更新与网络探活。

3. **自动联动双总账更新**
   - 每次成功归约并沉淀领域母本后，`sync_desktop()` 必须同时执行：
     - ① 更新桌面《饥荒工坊研读总账本.md》；
     - ② 全量重构并写入 `docs/workshop_studies/README.md` 主总览索引；
     - ③ 同步更新所在分类目录下的分卷 `README.md`。

4. **每次启动前强制自检读取**
   - `daemon_8_workers.py` 在 `run()` 入口启动时，必须首先读取并校验本文档的存在与内容，确认规范加载成功后再启动工作线程。

## 四、权威 Skill 沉淀与演进规范（老爹工业级标准）

> 严禁无序堆量与重复创建！大模型工程体系中，盲目堆砌碎片化、低质微型 Skill 会导致 RAG 检索中毒、上下文稀释以及注意力分散。知识库永远追求**高信息密度的工业级范式**。

### 1. 两层合一终极文档/Skill 标准骨架格式（Doc-as-Skill 范式）
每个文档即是一篇高水准架构博客，同时又是即插即用的黄金 Skill。坚决杜绝“无代码的空谈文档”与“无背景的代码碎片”。严格执行以下 **6 大标准板块**：

```markdown
# 饥荒工业级最佳实践范式：[机制/领域全称]

> 对应工坊权威基准：Mod [ID] (`[英文原名]`) 及衍生变体
> 技术标签：[如：客机协程、预测打断、网络拓扑、防抖、对象池]

## 一、架构背景与设计哲学（人类友好阅读层）
1. **痛点场景**：官方原生机制在什么情况下会卡顿/失效/崩溃？
2. **架构决策**：为什么选用该设计（如纯客机预测 vs 服务端权威）？
3. **关键时序与拓扑**：附带文字生命周期或时序流程（Client -> RPC -> Server -> SG 状态机）。

## 二、核心数学与底层算法（技术硬核层）
- 若涉及几何/网格：列出仿射矩阵变换公式与离散吸附计算；
- 若涉及队列/调度：列出状态机步进、时间预算（Time Budget）分片算法；
```

### 2. 重复/相似功能 Skill 处理铁律（绝对禁止新建重复项）
当解析的新 MOD 与已有 Skill 在功能领域上存在重合时，**绝对禁止直接新建一个重复文件**。必须按以下标准处理：

1. **增量演进与变体扩展（Merge & Evolve - 母本增强）**
   - **执行原则**：一个技术功能领域，系统内**永远只有一份权威母本规范**。
   - **操作方法**：直接在原有黄金 Skill 文档末尾追加演进章节：
     - `## 五、进阶拓扑演进与变体分支（来源于 Mod [ID]）`
     - 详细剖析新模组在原范式之上的创新切片（例如原范式实现了动作队列，新模组补充了骑牛/变身状态下的动作中断补偿，则将补偿算法直接合入母本），使母本随时间不断进化为终极全解。

2. **追加方案对比矩阵与权衡取舍（Trade-off Matrix - 说明差异与好处，供开发者自行选择）**
   - **执行原则**：如果新模组采用了与老模组完全不同的技术选型（如：老模组采用 Netvars 广播属性，新模组采用全局 RPC 瞬时推），必须在母本中追加对比章节，详细剖析两者差异、优缺点与收益代价，让调用方根据实际业务场景自行权衡选择。
   - **标准对比表格范式**：

| 技术选型方案 | 核心技术原理 | 优势与收益 | 代价与潜在风险 | 推荐适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **方案 A：[老模组选型]** | [简述实现机制] | [如：零客户端幽灵、带宽低] | [如：强依赖网络时延] | [如：低频长效状态同步] |
| **方案 B：[新模组选型]** | [简述实现机制] | [如：客机即时响应无卡顿] | [如：需客户端重调和预测] | [如：高频动作/连击判定] |

3. **正交切片独立立项（仅限全新正交机制）**
   - 若新模组仅在基础功能上附带了完全正交、独立的硬核新机制（例如背包模组中附带了基于标签过滤的“全自动漏斗分流物流系统”），则**基础背包部分直接引用原有背包母本**，仅将创新的“自动分流物流拓扑”作为全新的正交 Skill 单独立项。

### 3. 物理存储与 Docsify 目录映射铁律（双端同源）
- **核心沉淀主干**：所有归约后的领域母本统一存放在 `docs/workshop_studies/` 各专题目录下（例如 `docs/workshop_studies/02_动作交互与自动化类/study_client_action_queue.md`）。
- **Docsify SPA 路由兼容**：所有内部链接与侧边栏 `_sidebar.md` 引用**必须显式附带 `.md` 后缀**，且使用绝对站点根路径（如 `/docs/workshop_studies/.../xxx.md`），严禁使用 `./` 相对路径，确保单页应用跳转绝不 404。
- **Skill 库映射**：`anli/skills/` 保持与 `docs/workshop_studies/` 黄金母本的同源镜像同步，确保大模型 Agent 工具调用与人类网页查阅使用完全一致的规范定本。


### 3.1.1 铁律：生产级代码切片完整性约束（零截断、强闭合）
- **严禁残缺片段**：母本中的代码切片严禁出现末尾 `function()`、`then`、`do` 等悬空未闭合状态，严禁截断一半代码。
- **作用域自闭环**：代码块必须完整闭合（每一个 `function/then/do` 必须匹配对应的 `end` 闭包）。
- **可运行与可移植**：提取的切面代码必须具备完整的局部变量声明（`local GLOBAL = GLOBAL`）、上下文挂载点（如 `AddPrefabPostInit`、`AddComponentPostInit`）及完整函数体，读者复制即可直接使用。


### 3.1.2 铁律：多切片多角度覆盖原则（行数不设限、合理必全录）
- **代码行数无上限**：严禁为了追求字数或行数限制而阉割真实逻辑；只要切片属于核心架构切面，必须完整自闭环保留。
- **多切面多角度并存**：一个硬核模组往往涉及多个生命周期钩子（如 `AddComponentPostInit` + `AddPrefabPostInit` + `SendModRPCToServer`），只要具备工业借鉴价值，应在【第三章：标准化生产级代码范式】中分节并行展示多个完整切面代码块，全景呈现协同原理。
