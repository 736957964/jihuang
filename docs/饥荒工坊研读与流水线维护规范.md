# 饥荒工坊研读流水线执行与架构规范（老爹权威标准）

> 本规范由管理员（老爹）于 2026/10/31 明确立项并强制执行。
> **铁律执行原则**：每次启动、重启、维护或扩展饥荒工坊拉取任务与代码生成前，**必须首先完整读取本规范**，严格遵循架构标准，禁止遗忘，禁止擅自简写或截断！

---

## 一、核心原则与全量可见性要求

1. **所有人公开可查，绝对禁止信息折叠**
   - 文档面向全体开发者与社区玩家，严禁出现类似“篇幅所限仅展示前 N 个，其余详见桌面”等偷懒或截断行为。
   - 所有已研读的 MOD 必须 100% 具备公开索引和直接跳转路径。

2. **按功能领域深度分类归档**
   - 所有单模组分析报告（`study_<id>_<name>.md`）除了在总索引登记外，必须完整归入七大核心功能分卷：
     - `01_UI与HUD界面类`
     - `02_动作交互与自动化类`
     - `03_物品容器与背包扩展类`
     - `04_网络同步与RPC辅助类`
     - `05_语言汉化与文本显示类`
     - `06_大型综合与机制扩展类`
     - `07_实体玩法与数值机制类`

3. **分类必须具备全景横向架构综述**
   - 每个分类目录下必须维护专有的 `README.md`，不能只有模组列表。
   - 综述必须横向提炼：
     - **设计范式与生命周期管理**：各 MOD 公用的注册时序、环境隔离。
     - **底层关键 Hook 与组件**：如 `AddPrefabPostInit`、`AddClassPostConstruct`、`BufferedAction`、`net_var`、`RPC`。
     - **高频避坑与生产级守则**：时序空指针防御、网络同步广播开销、存档污染防范。

4. **Skill 沉淀必须以“功能实现”为核心提炼干货（老爹严令）**
   - **严禁流水账**：严禁仅记录“这个 MOD 做了啥、作者是谁”的流水账复述！
   - **吃透底层精髓**：核心是“通过这个 MOD 学习到了什么底层技术机制”，萃取可以直接复用、移植到其他 Mod 开发中的通用代码片段和技术范式！
   - **按功能检索导向**：Skill 索引和归档必须以【功能诉求】为第一检索依据（例如：`血条与状态HUD挂载`、`动作拦截与SG替换`、`网络变量同步与RPC`、`大容量容器与背包网络拓扑` 等），使任何开发者想做某项具体功能时，搜索功能即能直接获取标准解法与现成干货代码！

## 二、自动化流水线脚本规范（daemon_8_workers.py）

1. **自动加码机制**
   - 候选池安全储备不少于 200 个，不足时必须自动发起深层翻页（至少 15 页）爬取工坊热门与高分榜。
   - 线程池固定为 8 线程高并发，严格遵守“SteamCMD 串行加锁下载、多线程并行源码静态解析”的最佳架构，防止单实例冲突死锁。

2. **自动联动双总账更新**
   - 每次成功解析并沉淀 MOD 后，`sync_desktop()` 必须同时执行：
     - ① 更新桌面《饥荒工坊研读总账本.md》；
     - ② 全量重构并写入 `docs/workshop_studies/README.md` 主总览索引；
     - ③ 同步更新所在分类目录下的分卷 `README.md`。

3. **每次启动前强制自检读取**
   - `daemon_8_workers.py` 在 `run()` 入口启动时，必须首先读取并校验本文档的存在与内容，确认规范加载成功后再启动工作线程。

## 三、QQ 消息发送规范（技术防坑）

- **换行转义防坑**：
  在调用消息发送接口时，必须传递真实换行字符（`\n`），严禁二次转义成字面量 `\\n`，以防 QQ 气泡直接渲染出斜杠和 n。
