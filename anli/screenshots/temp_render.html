饥荒题目评审：利用鼠标 RPC 绕过 Busy 检查防掉装方案可行性分析 技术方案深度评审

一、核心原理与可行性判定

判定结果：【完全可行，且是高玩/连击防掉装的最佳解法】

在���饥荒联机版》中，麋鹿鹅（Moose/Goose）吼叫武器震落、以及普通玩家被冰冻/硬直时，角色状态机（StateGraph）会被打上 "busy" 标签。

  • 常规行为 RPC（如 ACTIONS.UNEQUIP / USEITEM）：服务端在 bufferedaction 执行前必须校验 not inst.sg:HasStateTag("busy")，因此硬直中发出的普通切装动作会被底层抛弃或延迟；
  • 鼠标背包 RPC（如 TakeActiveItemFromAll / MoveItemFromAllContainer）：属于客户端原生 UI 级网络同步通道，它是直接对玩家 inventory / activeitem 进行原子化状态迁��，原生不经过 StateGraph 的 busy 动作拦截！

二、一帧完成全部操作的时序链（防鼠标占用）

-- 客户端同一渲染帧/网络Tick内连续发送的原子操作：
1. 发送 RPC.TakeActiveItemFromAll(equip_slot)  --> 将手部即将被震落的武器拿起至光标 (ActiveItem)
2. 发送 RPC.MoveItemFromAllContainer(target_empty_slot) --> 立即将 ActiveItem 放入背包指定空位
3. 校验并还原：光标恢复清空，武器已安全避入背包，0帧占用鼠标！

三、工程落地的 3 个关键避坑点

  • 1. 网络延时丢包与重发时序：同一帧连发多个网络包必须顺序到达，否则服务端先收到放下后收到拿起会导致空操作，建议使用标准封装的同步包；
  • 2. 客户端预测状态保护：拿起武器到光标的瞬间，如果客户端自身有 UI 刷新，要拦截 SetCursorItem 产生的视觉抽搐；
  • 3. 背包满格异常兜底：执行前必须本地先嗅探 inst.replica.inventory 确定有且仅有可用空位，否则 ActiveItem 悬在鼠标上反而会导致无法走位。
