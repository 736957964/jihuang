## 一、架构背景与设计哲学
本范式旨在解决饥荒联机版中 大霜鲨更多交易次数 涉及的架构协同难题。
在官方源码机制下，原版逻辑对相关切面具备较强的封闭性。通过精准挂载钩子、隔离脏标记通信及遵循生命周期规范，实现无侵入式工业级扩展。

## 二、核心底层算法与网络拓扑机制
1. **系统注入切面与挂载拓扑**：
   - 提取到核心切面钩子：`['AddPrefabPostInit:sharkboi']`；
   - 依赖官方底层实体生命周期：在 `PreInit` 完成网络数据对齐，在 `PostInit` 挂载业务监听，确保跨客户端无缝通信。

## 三、标准化生产级代码范式（可直接移植）

```lua
-- ============================================================================
-- 生产级架构复刻切面范式 (提取自 Mod 3771598087)
-- ============================================================================
local GLOBAL = GLOBAL

-- ==================== 大霜鲨预处理 ====================
AddPrefabPostInit("sharkboi", function(inst)
    -- 只在主机端执行（避免客户端干扰）
    if not TheWorld.ismastersim then
        return
    end

    -- 1. 覆写 MakeTrader：每次进入交易状态时按配置初始化次数
    local old_maketrader = inst.MakeTrader
    inst.MakeTrader = function(inst2, ...)
        if old_maketrader ~= nil then
            old_maketrader(inst2, ...)
        end
        SetStockForTrader(inst2, GetTargetTrades())
    end

    -- 2. 覆写 OnSave：保存当前剩余交易次数
    local old_onsave = inst.OnSave
    inst.OnSave = function(inst2, data)
        if old_onsave ~= nil then
            old_onsave(inst2, data)
        end
        if inst2.components ~= nil and inst2.components.trader ~= nil and inst2.stock ~= nil then
            data[SAVE_KEY] = inst2.stock
        end
    end

    -- 3. 覆写 OnLoad：读档时优先恢复剩余次数，没有则按配置初始化
    local old_onload = inst.OnLoad
    inst.OnLoad = function(inst2, data)
        if old_onload ~= nil then
            old_onload(inst2, data)
        end

        if inst2.components ~= nil and inst2.components.trader ~= nil then
            local saved_stock = data ~= nil and data[SAVE_KEY] or nil
            if saved_stock ~= nil and type(saved_stock) == "number" then
                -- 有存档值：恢复剩余次数
                SetStockForTrader(inst2, saved_stock)
            else
                -- 无存档值（首次生成）：按配置初始化
                SetStockForTrader(inst2, GetTargetTrades())
            end
        end
    end
end)
```

## 四、方案对比矩阵与权衡取舍（Trade-off Matrix）

| 技术选型方案 | 核心技术原理 | 优势与收益 | 代价与潜在风险 | 推荐适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **方案 A：PostInit 深度切面（本母本）** | 挂载官方标准生命周期注入点 | 原生兼容性高、零侵入、支持跨 Mod 协同 | 需精确处理加载先后时序 | 绝大多数公网联机与模组服 |
| **方案 B：全局暴力覆写（Anti-Pattern）** | 篡改全局函数或暴力替换 Class | 编写简单快速、无需排查依赖链 | 极易造成 Mod 相互排斥及坏档 | 个人单机测试环境 |

## 五、进阶拓扑演进与变体分支
- **分支 1（网络预测优化）**：若需支持客机零延迟预表现，可在客户端副本（Replica）装载本地预表现动画。
- **分支 2（高负载防抖截流）**：在高频 RPC 或高频网络事件中挂载脏标记脏池，防止包泛洪。

## 六、踩坑与反模式避错指南（防御性闭环）
1. **网络变量声明时机**：所有 `net_*` 必须在 `inst.entity:AddNetwork()` 后、`SetPristine()` 前注册，严禁在预制体后处理的尾部动态挂载。
2. **重入锁防御**：在复杂事件分发时，务必维护实体级别的布尔标记，防止死循环递归。
